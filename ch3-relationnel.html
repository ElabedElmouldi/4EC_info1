3. Les bases de données relationnelles

Objectifs
  • Définir table, champ, enregistrement et type de données.
  • Définir clé primaire, clé composée et clé étrangère.
  • Reconnaître les trois types de relations.
  • Expliquer l'intégrité des données.
Base de données relationnelle. Base dont les données sont organisées en tables (appelées aussi relations) à deux dimensions, reliées entre elles par des clés. Chaque table décrit un seul sujet (les clients, les produits…).
Table (relation). Tableau de lignes et de colonnes qui regroupe les données d'un même sujet. Son nom est unique dans la base ; elle porte un seul sujet.
Exemple : la table CLIENT.
Champ (attribut, colonne). Une propriété décrivant le sujet de la table. Il a un nom unique dans la table et un type de données.
Exemples : Nom, Ville, Téléphone dans CLIENT.
Enregistrement (n-uplet, ligne). Ensemble des valeurs des champs pour un élément de la table : une ligne complète.
Exemple : (1, Ben Ali, Ahmed, Sfax, 74100001) est un enregistrement de CLIENT.
Domaine / type de données. Ensemble des valeurs permises pour un champ (texte, nombre entier, date, monétaire, Oui/Non…). Il empêche de saisir une valeur incohérente (du texte dans un prix).
Valeur Null. Absence de valeur : champ non renseigné. Elle est différente de zéro et du texte vide. Elle est interdite dans une clé primaire.
Clé primaire. Champ (ou groupe de champs) dont la valeur identifie de façon unique chaque enregistrement de la table. Elle doit être unique, jamais vide, stable (elle ne change pas) et la plus courte possible. Une table n'en a qu'une.
Exemples : IdClient dans CLIENT ; le nom d'un client ne convient pas (deux clients peuvent s'appeler pareil).
Clé composée. Clé primaire formée de plusieurs champs, dont la combinaison est unique.
Exemple : (NumCommande, CodeProduit) dans LIGNE_COMMANDE : un produit apparaît une seule fois dans une commande.
Clé étrangère. Champ d'une table qui reprend les valeurs de la clé primaire d'une autre table : c'est lui qui crée le lien entre les deux tables. Ses valeurs doivent exister dans la table liée (ou être Null).
Exemple : IdClient dans COMMANDE renvoie à IdClient de CLIENT.
Relation (association) entre tables. Lien logique entre deux tables, établi par une clé primaire et une clé étrangère de même type. Son type dépend de la cardinalité (nombre d'enregistrements associés de chaque côté) :
  • Un à un (1-1) : un enregistrement de A correspond à au plus un de B, et réciproquement.
  • Un à plusieurs (1-∞) : un enregistrement de A correspond à plusieurs de B, mais chaque enregistrement de B à un seul de A. Un client passe plusieurs commandes.
  • Plusieurs à plusieurs (∞-∞) : plusieurs de A correspondent à plusieurs de B ; elle se réalise avec une table intermédiaire. Une commande contient plusieurs produits et un produit figure dans plusieurs commandes.
Intégrité des données. Ensemble de règles qui garantissent que les données restent exactes :
  • de domaine : chaque valeur respecte le type et les règles du champ ;
  • d'entité : la clé primaire est unique et non vide ;
  • référentielle : une clé étrangère ne peut pas désigner un enregistrement qui n'existe pas ; on ne peut pas supprimer un enregistrement encore utilisé ailleurs.
Redondance. Répétition inutile d'une même information. Elle provoque des pertes de place et des incohérences ; on l'évite en créant des tables séparées reliées par des clés.
Exemple : écrire le nom et la ville du client dans chaque commande au lieu de ne stocker que IdClient.

Exemple : extrait de la table CLIENT

IdClient (clé primaire)NomPrénomVille
1Ben AliAhmedSfax
2TrabelsiAmiraTunis

Les en-têtes sont les champs, chaque ligne est un enregistrement, la première colonne est la clé primaire.

Schéma relationnel de l'exemple fil rouge (gestion des commandes) :

CLIENT (IdClient, Nom, Prénom, Ville, Téléphone)
PRODUIT (CodeProduit, Désignation, PrixUnitaire, Stock)
COMMANDE (NumCommande, DateCommande, #IdClient)
LIGNE_COMMANDE (#NumCommande, #CodeProduit, Quantité)
Souligné = clé primaire ; # = clé étrangère.

À retenir
  • Table = sujet ; champ = colonne ; enregistrement = ligne.
  • La clé primaire identifie chaque ligne. La clé étrangère crée le lien entre deux tables.
  • Relations : un à un, un à plusieurs, plusieurs à plusieurs (table intermédiaire).
